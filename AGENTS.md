# Контекст проекта

- Проект является тестовым заданием Smart Sender для Senior Frontend Engineer.
- `TASK.md` содержит оригинальные требования и является основным источником истины.
- Перед реализацией новых функций необходимо учитывать `TASK.md`.
- `TASK.md` нельзя изменять без прямого указания пользователя.

# Архитектура

- Использовать React и TypeScript strict mode.
- Разделять API-логику, состояние приложения и UI.
- Соблюдать API-контракт из `TASK.md`.
- Использовать MSW для имитации backend.
- Не создавать сложную инфраструктуру или монорепозиторий.
- Не добавлять ненужные зависимости и абстракции.
- Предпочитать простые, читаемые и типобезопасные решения.

# Рабочий процесс

- Выполнять только явно запрошенные изменения.
- Не реализовывать функциональность будущих этапов.
- Сохранять существующий стиль форматирования.
- Не переписывать несвязанные файлы.
- Не добавлять лишние комментарии.
- Не изменять `README.md` без отдельного запроса.
- Не выполнять Git-команды.
- Не создавать commit и не выполнять push.
- Не запускать format, lint, build, test, git diff, git status или другие проверки без отдельного указания.
- Не исправлять несвязанные проблемы без согласования.
- Все объяснения, отчёты и ответы писать на русском языке.
- Весь новый и изменяемый код должен сразу соответствовать существующим настройкам Prettier и ESLint.
- Перед написанием кода учитывать конфигурацию форматирования и существующий стиль проекта.
- Сохранять принятые правила отступов, кавычек, переносов строк, trailing commas и порядка импортов.
- Не изменять форматирование файлов, не относящихся к текущей задаче.
- Не запускать Prettier, ESLint, TypeScript, build, тесты и другие проверки самостоятельно.
- Не выполнять Git-команды. Все проверки и Git-операции пользователь выполняет вручную.
